今天在与同事聊 Agent 的时候，在聊完之后，我其实有想复盘，但是因为当时更想要去休息一下，去刷刷短视频来放松一下，也就暂时搁置。

主要聊到的是以下内容：

  1. 你的 Agent 使用的是什么架构？
  2. 在召回率低的时候，你会怎么做？系统性的思考和出发点。
  3. 有没有考虑过使用知识图谱来解决召回率低的问题？
  4. 有没有考虑过使用知识图谱，召回 node 之间的路径上对应的 chunk
    简单问题使用 react，难的问题使用 plan-and-execute，多步骤去解决。

在你使用 agent 的过程中出现了什么问题，你怎么去解决的。要模拟真实场景

  • 使用 AI 去帮助我生成几个 agent 在运行的时候会遇到什么问题，然后怎么解决的。我会去想好，问题的原因是什么？有哪些解决方案？为什么要选择当前的解决方案，你的考量是什么？
    多使用 AI 去帮助自己模拟真实的场景。

我发现有的时候畏难，主要是因为想要一下子将事情给做好。我以前想的复盘是，需要将我刚刚遇到的所有问题全部都记录下来，需要将我们对话的所有内容，方方面面都记录下来，这样才算是真正地复盘，否则遗漏任何一点对我来说都是灾难，还不如不记录。
后面我突然想到，如果我针对每次的对话，每次的面试都能够收获一点东西的，那么我使用题海战术去面试和与人交流，那这样我收获的内容就算不是 100%，如果能够得到大量实践之后的 80%的经验，那从最后的数量上来说我也是挣到了，于是我就不再纠结于全部，只要是每次都有一点收获，对过去的我来说都是一点金木，积少成多。
而且我接纳自己记不住所有的对话/学习内容，我接纳自己只能够吸收 70%的对话和学习的内容，但是也没有关系！我每次对话都能够学习到知识！
我就用概率的思想去学习和复盘。如果我这次复盘了，那收获的经验的概率值就是 0.7，如果我什么都不干，或者追求完美，后者的期望是 0.5 都不到，所以我还不如让自己放平心态，抱着能学一点就学一点的松弛的想法去学习和复盘，这样轻松的想法，不搞定所有一切的想法，不完美主义的想法，就能够让我前进的步伐轻盈很多。

AI+Docker部署记录-在华为云T4服务器上

Posted on 2026-07-02 Word count in article: 1.4k Reading time ≈ 5 mins.

任务

简单说一下我的部署任务。主要是部署我的项目镜像到客户的服务器中，以及项目镜像依赖的embedding的服务镜像。
在客户的服务器中，只有docker环境，不能联网，有一张T4显卡，已经安装了驱动，CPU最大的线程数是1092（好像？）。

部署我的项目镜像，只需要embedding的服务。其他的环境都已经打包好放至镜像中。
部署embedding的服务，也需要使用Docker镜像打包环境的方式去部署。我当前选择的是vllm/vllm-openai:v0.9.1。
调用embedding服务的目的是为了进行语义分块。

遇到的问题

  1. 最开始报错RuntimeError: CPU dispatcher tracer already initlized
  2. 解决,通过环境变量禁用 CPU 调度优化。
  3. 报错：ERROR 06-25 00:38:21 [engine.py:458] RuntimeError: Unexpected error from cudaGetDeviceCount(). Did you run some cuda functions before calling NumCudaDevices() that might have already set an error? Error 304: OS call failed or operation not supported on this OS
  4. 未解决，尝试下载nvcc，并且部署，发现安装不上，配置环境变量失败。通过grep，find的方式找到本地有一个nvcc，于是配置环境变量，构建软链接，于是nvcc --version是成功了，但是依旧报错cudaGetDeviceCount().
  5. 最后放弃，我使用embedding的目的是为了去做分块，使用语义分块，现在放弃语义分块，直接使用迭代分块。启动我的项目镜像，发现调用的LLM的服务的host无法resolved，ping也无法ping通，最后发现是没有开网络策略，截止当前文章，仍然在开策略中……

部署操作

  1. 在与 AI聊天，下指令的时候，需要说明让它创建 requirements.txt，并且指定清华源去下载 python 包，这样会更快一点，在任何一个能够访问互联网的服务器都会快一点。pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
  2. 在测试某个接口的时候，最好创建一个独立的文件。例如在测试 LLM 的时候，不要使用一个 config.yaml, 又使用一个 test 文件，这样加载起来很麻烦，在测试 database，embedding 的时候也应该这样。测试起来更加方便。创建一个 test_milvus.py, test_embedding.py, test_llm.py 文件去测试。
  3. 在要求 docker 打镜像之后，要求将镜像以及 API 服务启动的命令放在 README.md 中。
  4. docker 操作，见下面一个章节。

Docker 操作

–name

如果不设置容器的名字的话，那么每次启动容器的时候都会去创建新的名字，在删除容器的时候都需要打容器的名字很麻烦。需要直接制定–name 之后再去启动容器，这样会更加方便。

– privileged

出现报错：runtimeerror can't start new thread 时候使用。

在容器内使用多线程时，如果 docker 的容器权限不高，那么就会出现无法创建多线程的问题。此时遇到线程问题，首先去看看能不能够通过增加一个--privileged 函数去实现。

–entrypoint

想要仅仅使用容器中的环境，而不使用镜像创建时的启动脚本，可以使用--entrypoint 去要求 docker 在启动的时候忽视容器的启动脚本。一般在需要容器中的 python 或者其他软件的应用环境时，会使用--entrypoint。

–rm

在容器 stop 掉，或者因为异常报错无法启动，或者在–it 容器起来之后调试之后立马删除容器，可以使用这个命令，会非常方便，一般的时候在测试的时候使用，在生产环境中一般不这样使用。

vim 无法编辑

  1. docker stop
  2. docker rm
  3. docker run，映射--volume
  4. 再在容器的环境中去映射之后的脚本

没有解决的 docker 容器的问题

cudaGetCoreDevice(), 一直都没有解决。当前现象是，在 docker 容器之外能够方位 nvidia-smi，但是在需要使用的 docker 容器中，就 cuda not avaliable，这很奇怪，不知道为什么。

我尝试了很多方法：

  1. 怀疑是我使用的vllm/vllm-openai的版本镜像太高了，开始是v0.9.1, 降到v0.5.1依旧无法解决这个问题。在降低版本的过程发现，vllm/vllm-openai从v0.6.6.post1才开始支持--task embed这个参数，在vllm/vllm-openai的v0.6.4.post1的参数还是--task embedding, 在v0.5.x还不支持--task这个参数。
  2. 安装cuda，当前nvcc --version出来显示我没有安装cuda，在我使用cuda_12.2.0_535.54.03_linux.zip 去安装的时候，发现通过配置环境变量等各种方法都没有配置上，虽然通过nvidia-smi显示最高支持的cuda的版本是12.4，但是我无法去安装。
    在通过ls和find，grep查找nvcc的时候，发现在某个cuda文件夹下有一个版本未11.4的文件夹，尝试在环境变量中配置nvcc未这个11.4的cuda。于是发现虽然配置成功了，但是容器在启动的时候发现还是报错cudaGetDeviceCount()的错误。不知道是为啥。

记录使用Cursor做的事情

Posted on 2026-07-01 Word count in article: 813 Reading time ≈ 3 mins.

开发类

  1. 在项目文件夹下新建 specs/spec.md 文件，所有的长文本的需求可以放在 spec.md 中，让 cursor 去读取你的文件，根据你文件的要求去开发。同时也可以让 cursor 将开发的结果和结论放在 spec.md 中。
  2. 让 Cursor 去根据 spec.md 去构建镜像，告诉它镜像中需要哪些文件，基础的镜像是什么，然后它会自己去构建 requirements.txt。你可以要求它使用 Dockerfile，或者 docker-compose 去构建镜像，注意在使用 pip 下载 python 包的时候告诉它使用清华源镜像，不然会很慢。另外，注意配置 dockerignore,告诉它需要删除哪些不用的日志文件。
  3. 根据 debug 的结果，将 terminal 中运行的结果加入到 cursor 的输入的上下文中，并且告诉它运行的代码文件，问它为什么会出现这个问题，怎么解决这个问题。
  4. 在 cursor 的边栏输入框中，选中一些文件，让它基于你的需求去对选中文件去进行改造和 debug。cursor 能够访问的文件 不仅仅局限于选中的文件，还可以读取整个项目目录的文件，如果在它的 agent 判断需要读取其他的文件的情况下。

操作类

  1. 帮助清理磁盘空间，首先先找系统盘哪些文件可以删除，然后告诉它可以去删除哪些文件。在删除文件之前会找你去确认，一定要仔细查看它要删除的目录。
  2. 移动 docker 和 conda 包的存储位置，之前本来放在系统盘中，现在放在数据盘中。
  3. 帮助挂在硬盘。在云服务器上挂载了硬盘，但是在服务器的命令行中没有配置，那么可以告诉 cursor 你的数据盘的硬盘的大小，然后开始去做配置。
  4. 打开 cursor 的内置浏览器，打开并且登录你想要让 cursor 访问的网站，让 cursor 基于打开的网页去进行解读、总结和内容生成。

学习类

  1. 基础：给某个文件新增注释，给某个文件生成函数注释，解释某个函数的功能，让 cursor 去帮助你追踪某个函数的功能链路，让你知道在整个流程中，这个函数的作用。
  2. 进阶：生成项目的 readme.md，生成项目的流程图和架构图。

Cursor Agent

  1. 将需求放在项目根目录下的 specs/spec.md 中，打开 Agent window，让 cursor 基于 specs/spec.md 去开发。可以有多种要求（1）根据 specs/spec.md 去进行开发，（2）根据 specs/spec.md ，和我一起讨论我的任务的要求，并且跟我一起明确讨论需求中不明确的地方，然后开始讨论，（3）跟我 specs/spec.md 中的任务，和我一起讨论实现的方案，然后开始开发，最后将计划，以及任务的结果和部署方式放在 specs/spec.md 中。
  2. 让 Cursor Agent 去阅读你的项目，并且基于你的项目去进行改造，生成简历描述，生成技术 PPT，以及项目的架构、项目流程图。

还有剪辑视频，有的时候喜欢拍沉浸式，拍小猫在睡觉的视频，经常就是睡着，看着不动。但是其实小猫是动的，就是在慢慢看的时候看不出来，但是你在倍速的时候，或者快速拖动进度条的时候，小猫的肚子就是一动一动的，它在动的。在拍摄的时候我就是想记录小猫，在后期观看的时候，觉得小猫不动，于是就有点沮丧，不知道该不该发出去。我在看小猫咪的安安静静睡觉的时候，我是觉得内心是比较安静的，我不知道刷到我小猫视频的人看到会不会也一样觉得很安静，所以我会犹豫要不要发出去。在剪辑的时候，我拖动进度条发现小猫肚子动的非常有节奏，如果倍速看也会有不一样的感受。在发布的时候，我看到小猫的的视频，我还是会觉得很安静。最后这个视频有5个赞，还是挺多的。我一遍犹豫着，一边去剪辑发布小猫的视频，发的视频多了，点赞量也上去了。
就剪辑上，我做事的每一步的心路历程都感受到自己的犹豫，但是还是蹑手蹑脚地前行了，有的不看好的视频，居然获得了大家的喜爱，这就让我很惊喜，有点不知道在剪辑视频的时候需不需要犹豫了。

还有写作的时候，经常脑子中有想法，但是就是拖延，因为我没有想到一个非常完整的写作大纲，我认为写出来的内容是零散、不成体系的，所以经常要求自己在落笔的时候要脑子清晰，知道自己要写什么，并且脑子里面有一个画面了才开始动手。最近有了这个博客，写作对我来说是一件很简单的事情。
我今年在自己的小本本上给自己立下了一个今年要写30篇文章的愿望，所以即便是在我知道自己脑子对一件事情思考的不是特别明白，但是有一种强烈想要表达的愿望时，在我有机会的时候，我就会开始去写作，去写一个粗糙的大纲，然后开始去写作。就这样，这一篇长长的，但是不成体系的思考，就诞生出来了。
我想要看到年底在复盘写作这个目标的时候，能够非常感谢过去在没有准备好就动手的自己。

最后，即便是中间有停顿20min，这篇文章依旧断断续续地完成了，也是对自己行动力的嘉赏。
还有一个我刚刚想到，就是很多人也很粗糙地过好了生活，走到了现在，我不必要求自己做到很好再去行动。我可以粗糙地行动，粗糙地写作文章，只要基本的意思描述清楚，那就能够进入到一个行动的循环里，总有能够让自己特别满意的文章，总有能够获得让自己满意的结果，总能够获得意外的惊喜。

做好所有的TODO List之后反而很难受，在想为什么压力大，为了什么

Posted on 2026-06-01 Word count in article: 1.5k Reading time ≈ 5 mins.

昨天（2026.5.31） 做了很多的事儿：

  1. 学习，准备记忆系统
  2. 学习，准备 RAG 的兜底方案
  3. 学习，准备意图识别的微调过程
  4. 生活，及时收下猫砂的快递
  5. 生活，清理衣服上的猫毛，洗衣服，晾衣服
  6. 生活，整理垃圾，扔垃圾
  7. 生活，洗澡、洗头
  8. 生活，晚饭自己做，吃的自己做的煎鸡翅。

感受：在做完生活上的一些杂务之后，觉得很舒服，一下子将我讨厌的事情都做完了，我会觉得自己的行动力很强，不需要将他们再积累去完成了。这是当天的感受，一下子做好这么多事情，感觉生活都变得轻松了。
第二天的感受：觉得很焦虑，自己花了那么多的时间去做家务，从 18：20-21：30，差不多三个小时的时间。

在我刚刚仔细算过之后，发现，这些时间不多啊，就是三个小时的时间，怎么就会让我这么焦虑。
是因为对比我学习的效率，做生活杂事的效率很低，因为我在学习的时候差不多 5min 的时间就能够学习 1 页的内容，三个小时的时间能够让我学习非常多页的内容。
而且昨天下午在学习的时候，我其实效率不是很高，在学习 1h 之后就会需要看 1h 的时间，中间夹杂着。其实在学习之后去刷手机，并不是一种很好的休息和学习的方式，一点都没让我放松。相当于是我学习的那个阶段，一直都处于一种活跃和紧绷的状态，其实不会太好受。
这样我就想明白了，为什么我晚上一直不想睡觉，是因为我的脑子认为我没有放松下来，我觉得看看小猫，刷刷淘宝能够让我自己放松下来，看小猫可以让我活在当下，但是刷淘宝并不会让自己安静下来。
就是两者之间的对比差异，让我觉得做生活上的杂事，浪费了我的时间，但是他们是必要的。如果我不洗衣服，那么接下来我就需要穿一些很久没穿的衣服/买衣服，如果我不洗头，会非常难受，我头油着和痒着，我将不会有心思去做其他的事情。
我当时就在想着，我一直在学习，在看手机，都没有时间去好好过在当下，去看看外面的景色，吹吹这绿色的风。

自然诞生了一个疑问，我什么时候能够好好地活在当下呢。

想念之前能够自由给自己做饭的状态，现在感觉不太爱自己，做饭吃的不是很均衡，经常吃的太油腻或者太素，营养总是跟不上，我经常感到头晕，以及肚子因为长期很饿有一种亏损的感觉。
想念之前，工作日好好上班，周末好好休息的日子，什么时候能够过上那种日子呢？
工资高，就是要承受对应的压力的，慢性的，长期的。但是其实缓慢的压力我是能够承受的，这种急剧，很重的压力，我承受不了太久，我非常清楚。
我在这个时候就能够经常刷到一些介绍很焦虑处理方法的视频，他们的大致方案不是让你逃避，而是让你与你的焦虑共存，告诉你的焦虑，我注意到你了。我会花时间来放松，但是也可以朝着你的目标前行。没有一个告诉自己可以完全停下来的，反正就是接受，然后前行。
在我有目标，有理性的时候，我认可，我能够做到。在我没有力气的时候，我可能就会抱怨，为什么人生需要这么累呢？
在周六的时候，我出去看车了，我看的车大概是 20 多万，我当时就在想一个事情，我努力就是为了有一辆这样的车吗？买一辆这样的车真的值得自己这么损害自己的身体，去收获持续性地压力，努力地去获得，真的会值得吗？

经常就会有这样的疑问。

我想起来了，其实快乐不跟你拥有什么产品相关，是跟你自洽，还有你的饮食、睡眠，身体的舒适度相关。其实花 1000 块钱，去买些自己平时舍不得买的东西，就能够让自己的物质上得到极大的满足，精神也同时被滋养了。不需要花那么多的钱，就能够做到，真的。
不要为了购买什么东西，而让自己的精神陷入到这种重压的循环中。
如果一定要接受到很大的压力，那一定是要自己特别想，是要变成自己特别想成为的人。
现在自己调整方向，将自己原本的目标给拿回来。我现在的努力不是为了一个非常高薪的工作，我是为了在职业上获得更好、更丰富的体验，为之后的生活去做准备，去完善更好的自己。我想去得到一份更好的职业体验，我想要努力，让自己的能力匹配到那样的环境中，所以我现在在努力，提升的知识的深度和广度，去匹配到那样的环境。
剩下的一切，交给自己选择的环境，和自己的初心：获得更好的职业体验。一切的努力和行动，都是为了获得更好地职业体验。更高的薪资，只是更好体验的产物。

我在努力，我在尝试自洽，我在尝试成长。
