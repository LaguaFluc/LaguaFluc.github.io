AI+Docker部署记录-在华为云T4服务器上

Posted on 2026-07-02 Word count in article: 1.4k Reading time ≈ 5 mins.

任务

简单说一下我的部署任务。主要是部署我的项目镜像到客户的服务器中，以及项目镜像依赖的embedding的服务镜像。
在客户的服务器中，只有docker环境，不能联网，有一张T4显卡，已经安装了驱动，CPU最大的线程数是1092（好像？）。

部署我的项目镜像，只需要embedding的服务。其他的环境都已经打包好放至镜像中。
部署embedding的服务，也需要使用Docker镜像打包环境的方式去部署。我当前选择的是vllm/vllm-openai:v0.9.1。
调用embedding服务的目的是为了进行语义分块。

遇到的问题

  1. 最开始报错RuntimeError: CPU dispatcher tracer already initlized
  2. 解决,通过环境变量禁用 CPU 调度优化。
  3. 报错：ERROR 06-25 00:38:21 [engine.py:458] RuntimeError: Unexpected error from cudaGetDeviceCount(). Did you run some cuda functions before calling NumCudaDevices() that might have already set an error? Error 304: OS call failed or operation not supported on this OS
  4. 未解决，尝试下载nvcc，并且部署，发现安装不上，配置环境变量失败。通过grep，find的方式找到本地有一个nvcc，于是配置环境变量，构建软链接，于是nvcc --version是成功了，但是依旧报错cudaGetDeviceCount().
  5. 最后放弃，我使用embedding的目的是为了去做分块，使用语义分块，现在放弃语义分块，直接使用迭代分块。启动我的项目镜像，发现调用的LLM的服务的host无法resolved，ping也无法ping通，最后发现是没有开网络策略，截止当前文章，仍然在开策略中……

部署操作

  1. 在与 AI聊天，下指令的时候，需要说明让它创建 requirements.txt，并且指定清华源去下载 python 包，这样会更快一点，在任何一个能够访问互联网的服务器都会快一点。pip install -r requirements.txt -i https://pypi.tuna.tsinghua.edu.cn/simple
  2. 在测试某个接口的时候，最好创建一个独立的文件。例如在测试 LLM 的时候，不要使用一个 config.yaml, 又使用一个 test 文件，这样加载起来很麻烦，在测试 database，embedding 的时候也应该这样。测试起来更加方便。创建一个 test_milvus.py, test_embedding.py, test_llm.py 文件去测试。
  3. 在要求 docker 打镜像之后，要求将镜像以及 API 服务启动的命令放在 README.md 中。
  4. docker 操作，见下面一个章节。

Docker 操作

–name

如果不设置容器的名字的话，那么每次启动容器的时候都会去创建新的名字，在删除容器的时候都需要打容器的名字很麻烦。需要直接制定–name 之后再去启动容器，这样会更加方便。

– privileged

出现报错：runtimeerror can't start new thread 时候使用。

在容器内使用多线程时，如果 docker 的容器权限不高，那么就会出现无法创建多线程的问题。此时遇到线程问题，首先去看看能不能够通过增加一个--privileged 函数去实现。

–entrypoint

想要仅仅使用容器中的环境，而不使用镜像创建时的启动脚本，可以使用--entrypoint 去要求 docker 在启动的时候忽视容器的启动脚本。一般在需要容器中的 python 或者其他软件的应用环境时，会使用--entrypoint。

–rm

在容器 stop 掉，或者因为异常报错无法启动，或者在–it 容器起来之后调试之后立马删除容器，可以使用这个命令，会非常方便，一般的时候在测试的时候使用，在生产环境中一般不这样使用。

vim 无法编辑

  1. docker stop
  2. docker rm
  3. docker run，映射--volume
  4. 再在容器的环境中去映射之后的脚本

没有解决的 docker 容器的问题

cudaGetCoreDevice(), 一直都没有解决。当前现象是，在 docker 容器之外能够方位 nvidia-smi，但是在需要使用的 docker 容器中，就 cuda not avaliable，这很奇怪，不知道为什么。

我尝试了很多方法：

  1. 怀疑是我使用的vllm/vllm-openai的版本镜像太高了，开始是v0.9.1, 降到v0.5.1依旧无法解决这个问题。在降低版本的过程发现，vllm/vllm-openai从v0.6.6.post1才开始支持--task embed这个参数，在vllm/vllm-openai的v0.6.4.post1的参数还是--task embedding, 在v0.5.x还不支持--task这个参数。
  2. 安装cuda，当前nvcc --version出来显示我没有安装cuda，在我使用cuda_12.2.0_535.54.03_linux.zip 去安装的时候，发现通过配置环境变量等各种方法都没有配置上，虽然通过nvidia-smi显示最高支持的cuda的版本是12.4，但是我无法去安装。
    在通过ls和find，grep查找nvcc的时候，发现在某个cuda文件夹下有一个版本未11.4的文件夹，尝试在环境变量中配置nvcc未这个11.4的cuda。于是发现虽然配置成功了，但是容器在启动的时候发现还是报错cudaGetDeviceCount()的错误。不知道是为啥。
